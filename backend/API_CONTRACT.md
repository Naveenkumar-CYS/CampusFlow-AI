# CampusFlow AI — Student & Admission API Contract (Day 2)

Base URL (local dev): `http://localhost:8000`
Base URL (shared/deployed): **TBD — fill in once deployed**

All request/response bodies are JSON. All timestamps are ISO-8601 UTC.

---

## Student ID format

`STU` + 7 digits, e.g. `STU2026001`. When a Student is created via Admission
approval, this is auto-derived from the admission's `application_number`
(see Admission ID format below) — `APP2026001` → `STU2026001`.

## Admission application_number format

`APP` + 7 digits, e.g. `APP2026001`. Caller-supplied at creation — not
auto-generated by the backend in Day 2 (Person C / the applicant-facing
form is responsible for generating a unique one, or ask the backend team
for a generation endpoint if needed later).

## Student Endpoints

### Create Student
```
POST /students
```
Request:
```json
{
  "student_id": "STU2026099",
  "name": "Example Student",
  "email": "student@example.com",
  "department": "Computer Science",
  "course": "B.Tech",
  "enrollment_year": 2026,
  "phone": "9876543210"
}
```
`phone` is optional, everything else required.

Response `201 Created`:
```json
{
  "id": "5609b9d3-862d-4836-9066-0d006c0e23ed",
  "student_id": "STU2026099",
  "name": "Example Student",
  "email": "student@example.com",
  "department": "Computer Science",
  "course": "B.Tech",
  "enrollment_year": 2026,
  "phone": "9876543210",
  "created_at": "2026-08-23T08:28:40.802432Z",
  "updated_at": "2026-08-23T08:28:40.802432Z"
}
```
Errors: `409 Conflict` if `student_id` already exists. `422` on missing/invalid fields.

### Get Student
```
GET /students/{student_id}
```
Response `200 OK`: same shape as above. `404 Not Found` if it doesn't exist.

### List Students
```
GET /students
```
Response `200 OK`: JSON array of the same object shape. No pagination in Day 2 — returns everything.

### Update Student
```
PATCH /students/{student_id}
```
Request — any subset of fields (all optional):
```json
{ "department": "Electrical Engineering" }
```
Response `200 OK`: full updated Student object. `404` if not found.

### Delete Student
```
DELETE /students/{student_id}
```
Response `204 No Content` on success.
`404` if not found.
`409 Conflict` if the Student has linked Admission records — deletion is
blocked, not cascaded (see README for why).

## Admission Endpoints

### Create Admission
```
POST /admissions
```
Request:
```json
{
  "application_number": "APP2026099",
  "applicant_name": "Example Applicant",
  "applicant_email": "applicant@example.com",
  "department": "Computer Science",
  "course": "B.Tech",
  "enrollment_year": 2026,
  "application_date": "2026-06-15",
  "admission_type": "regular"
}
```
`admission_type` optional (defaults to `"regular"`), everything else required.

Response `201 Created`:
```json
{
  "id": "e98d19c0-8d8a-4b06-b9bc-1274886a73d3",
  "application_number": "APP2026099",
  "student_id": null,
  "applicant_name": "Example Applicant",
  "applicant_email": "applicant@example.com",
  "department": "Computer Science",
  "course": "B.Tech",
  "enrollment_year": 2026,
  "application_date": "2026-06-15",
  "admission_type": "regular",
  "status": "APPLIED",
  "created_at": "2026-08-23T08:28:30.383154Z",
  "updated_at": "2026-08-23T08:28:30.383154Z"
}
```
`student_id` is `null` until the admission is approved. Errors: `409` on
duplicate `application_number`, `422` on missing/invalid fields.

### Get Admission
```
GET /admissions/{application_number}
```
Response `200 OK`: same shape. `404` if not found.

### List Admissions
```
GET /admissions
```
Response `200 OK`: JSON array. No pagination in Day 2.

### Update Admission (including status transitions)
```
PATCH /admissions/{application_number}
```
Request — any subset of fields:
```json
{ "status": "APPROVED" }
```
Valid `status` values: `APPLIED`, `UNDER_REVIEW`, `APPROVED`, `REJECTED`, `CANCELLED`.

**Important:** setting `status` to `"APPROVED"` automatically creates (or
links to, if it already exists) a Student record, and the response's
`student_id` field will be populated. This is a side effect Person C
should know about — approving an admission is not just a status change,
it provisions the Student.

Response `200 OK`: full updated Admission object. `404` if not found.
`422` on an invalid status string.

### Delete Admission
```
DELETE /admissions/{application_number}
```
Response `204 No Content`. `404` if not found. (No FK restriction here —
deleting an admission never deletes its linked Student.)

## Known limitations — Day 2

- No pagination on list endpoints.
- No authentication/authorization — anyone can call any endpoint.
- Admissions cannot be manually linked to a pre-existing Student — the
  only path to a linked `student_id` is the auto-create-on-approval flow.
  If you need "link this admission to an existing student" (e.g. a
  re-application), flag it — not built yet.
- `student_id` derivation from `application_number` (APP→STU prefix swap)
  is a Day-2 simplification. If application numbers ever don't start with
  `APP`, ask the backend team before relying on the derived format.
- No events are actually published yet (see EVENT_CONTRACT_PROPOSAL.md) —
  Person C should poll/re-fetch rather than expect a webhook/notification.
